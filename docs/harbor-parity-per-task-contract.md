# Harbor parity per-task pairing contract

The fix-plan section 6 calls for a per-task pairing artifact that
replaces the historical aggregate-means comparison. This document
records the contract, the file layout, and the validator expectations.

## Why the contract changed

The historical Harbor parity evidence compared aggregate means between
the native AuthZBench-SaaS scorer and the Harbor harness. That approach
is weak: two harnesses can have the same mean and still disagree on
individual tasks. A reviewer who wants to know whether the local
AuthZBench-SaaS scorer and the Harbor adapter agree on the same task
needs per-task pairing.

The historical aggregate-means file is preserved at
`artifact/historical/harbor-parity-experiment-aggregate-means.json` for
back-compat. New evidence generated by
`scripts/run_harbor_parity_experiment.py` must use the per-task pairing
contract described here.

## File layout

The new live file is `artifact/harbor-parity-experiment.json` and uses
schema `harbor-parity-experiment-v1`. Required fields:

- `schema_version` (must equal `harbor-parity-experiment-v1`)
- `evidence_status` (one of `current`, `historical_backcompat`,
  `blocked`; new live evidence is `current` or `blocked` if Harbor CLI
  is unavailable)
- `parity_methodology` (must be `per_task_pairing` for new live
  evidence)
- `parity_verified` (false when per-task pairing has not been computed
  from real runs; true only when every task in `task_ids` matches
  within `reward_tolerance`)
- `public_claim_boundary` (must not claim Harbor platform acceptance,
  Kaggle acceptance, hosted leaderboard readiness, SaaS-provider
  validation, external review, or third-party submissions)
- `harbor_per_task_rewards` (mapping of task_id to Harbor reward)
- `native_per_task_scores` (mapping of task_id to native score)
- `per_task_match` (mapping of task_id to bool)
- `per_task_match_count` (int)
- `per_task_match_rate` (float in [0,1] or null when unknown)
- `per_task_disagreements` (list of task_id where match is false)
- `parity_match_threshold` (must equal 1.0)
- `reward_tolerance` (must be `<= 1e-5`)

## Validator expectations

`scripts/validate_harbor_parity_experiment.py` enforces:

- `parity_verified=true` requires `parity_methodology=per_task_pairing`
- `parity_verified=true` requires `evidence_status=current` (or
  `historical_backcompat` with the `aggregate_means` methodology)
- plan 6.2 cross-direction: any payload with `evidence_status=current`
  must declare `parity_methodology=per_task_pairing` regardless of
  whether `parity_verified` is true. This rule is not relaxed by the
  `--allow-aggregate-means-backcompat` flag.
- every task in `task_ids` must appear in both
  `harbor_per_task_rewards` and `native_per_task_scores` (when
  `parity_methodology=per_task_pairing`)
- `abs(native - harbor) <= reward_tolerance` for every task when
  `parity_verified=true`
- `per_task_disagreements` must list every task where the absolute
  delta exceeds the tolerance
- `per_task_match_count` and `per_task_match_rate` must be consistent
  with `per_task_match`
- `raw_harbor_jobs_tracked=false` and `private_artifacts_tracked=false`

## Current state

At the time of this writing, Harbor CLI is not installed. The live
`artifact/harbor-parity-experiment.json` is therefore marked
`evidence_status=blocked` and `parity_verified=false`. The
`per_task_pairing` contract is fully declared (methodology, threshold,
tolerance, empty per-task maps) so the next run of
`scripts/run_harbor_parity_experiment.py` can populate the maps without
schema changes.

The historical aggregate-means file is preserved for back-compat with
the pre per-task reward extraction era. The new live file points at
the historical file via `historical_backcompat_pointer` so reviewers
can find both.

## What v1 release evidence requires

- The live `artifact/harbor-parity-experiment.json` must be
  `evidence_status=current` and `parity_methodology=per_task_pairing`.
- `parity_verified` should be `true` when a real Harbor run completes
  and the per-task pairing matches within `reward_tolerance`.
- The historical file may be kept for traceability but does not
  contribute to the live v1 readiness gate.

## Reviewer questions

- Does the live file use `per_task_pairing`, or is it still
  `aggregate_means`?
- Is `parity_verified=true` only set when real per-task maps are
  populated?
- Is `reward_tolerance` strictly `<= 1e-5`?
- Is the historical file preserved at
  `artifact/historical/harbor-parity-experiment-aggregate-means.json`?
