# AuthZBench-SaaS v1.0-internal

> **See also:** [`docs/current-claim-boundary.md`](../current-claim-boundary.md) for the canonical claim ledger, and `docs/evidence-and-claims.md` for the per-evidence matrix.

Release name: `v1.0-internal`
Date: 2026-06-12 (internal release tag)
Status: **Complete under the internal/non-external release definition.**

## Status

`v1.0-internal` is the internal release-candidate cut. The v1 readiness gates
defined for the public-view readiness artifact pass under the
internal/non-external release definition. This release does **not** claim
external review, SaaS-provider validation, hosted public leaderboard
readiness, Harbor/Kaggle/platform acceptance, or third-party submissions.

`v1_ready: true` in
`artifact/expected-output/v1-readiness-public-view.json` is scoped to the
internal/public-view readiness gates only. It does not assert external
acceptance.

## What Is Included

- 6 synthetic SaaS fixture apps
- 60 public tasks across the 6 apps
- 48 maintainer-private holdout tasks, summarized only through public-safe
  count-level evidence
- 108 total public + private task scale
- Deterministic backend replay scoring
- Current 60-task scripted sanity baseline
- Repeated public no-tools baselines (Qwen, Claude Haiku 4.5, Claude Sonnet
  4.6, GLM-5, Claude Opus 4.6) and one repeated live HTTP tool-agent baseline
  for Claude Sonnet 4.6, kept in tracked evidence as historical 54-task
  baselines that are stale for current 60-task comparison until rerun
- Public task-quality gate contract and validator
- Public-safe Harbor adapter contract, skeleton builder, redaction, scorer
  bridge, blocker record, template validators, local preflight, runbook,
  parity methodology versioning, and runnable CLI
- Protected private-evaluation plumbing (active + shadow private packs with
  rotation metadata and host private-path denial)
- Docker-backed submission smoke evidence
- Release-candidate validation evidence
- Privacy checks, fresh-clone validation, and CI evidence
- Generated public-safe charts and task-quality matrix

## Validation Summary

Public-side validation commands that pass on the `v1.0-internal` tag:

```bash
python3 -m unittest discover -s tests
python3 scripts/validate_public.py --include-scripted-baseline
python3 scripts/validate_baseline_registry.py
python3 scripts/validate_harbor_parity_experiment.py
python3 scripts/validate_harbor_adapter_templates.py
python3 scripts/validate_v1_readiness.py \
  --allow-incomplete \
  --public-view \
  --expected-output artifact/expected-output/v1-readiness-public-view.json
```

Privacy check:

```bash
git ls-files tasks_private/holdout results captures docs/reviews/panel-logs harbor-jobs .harbor .handoff
```

The privacy check must print nothing for the public commit.
