# Agent / Tooling Review Packet

This packet is the v2 external-review handoff for an independent
AI-agent / tooling reviewer. It assumes the reviewer has read
[`docs/claims-and-evidence.md`](../claims-and-evidence.md)
and the
[`docs/reviews/external-review-intake.md`](external-review-intake.md)
intake form.

## Scope

- The agent harness contract (no-tools-model, tool-agent,
  scripted).
- The tool-access requirements, timeouts, retry policies, and
  temperature settings.
- The transcript and target-request-correlation contract.
- The submission bundle structure and validator.
- The Harbor adapter path (local adapter, local smoke, public
  parity, platform acceptance).

## Reviewer questions

1. **Harness contract**: Is the no-tools-model / tool-agent /
   scripted harness contract documented well enough that a reviewer
   can verify which row was generated by which harness without
   re-deriving the harness logic?
2. **Tool-access requirements**: Are the `tool_access` block, the
   `max_steps`, the `timeout_seconds`, the `max_http_requests`, the
   `retry_policy`, and the `temperature` settings clear and
   enforceable?
3. **Transcript schema**: Is the transcript schema documented well
   enough that a reviewer can replay any submission end-to-end
   against the seeded fixture?
4. **Target-request correlation**: For `harness_type: tool-agent`
   rows, is the `target_request_coverage_rate` definition and
   enforcement clear, and is the threshold that flags
   `review_flag: tool_budget_abuse` documented?
5. **Submission bundle structure**: Does
   `scripts/validate_submission_bundle.py` cover the bundle shapes
   a reviewer would want to reject (missing required files,
   run-id mismatch, harness-type / target-requests inconsistency,
   private-pack fingerprint mismatch, secret pattern embedded)?
6. **Harbor adapter path**: Is the four-level Harbor status table
   (repo-side adapter / local smoke / public parity / platform
   acceptance) consistently referenced in the runbook, the
   blockers artifact, and the readiness fixture? Is the
   `tests/test_harbor_claim_boundary.py` CI test broad enough to
   catch wording drift?
7. **Comparability**: Are two tool-agent rows comparable only when
   every tool-agent comparability key field matches, and is the
   validator refusing to assign the same key to two rows that
   differ in any of those fields?
